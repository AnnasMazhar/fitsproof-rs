## 2. Sibling comparison — the predicted-vs-measured gap (the product's credibility)

- Python edition (from its EVIDENCE Claim 8): predicted 39 MB, measured RSS 301.8 MB → **measured ≈ 7.7× predicted** (interpreter overhead, honestly labelled).
- Rust edition, reference model: predicted 0.057 GB (57 MB); measured process VmHWM 56.7–58.3 MB across `verify` + 25 stress runs → **measured ≈ 1.0× predicted**. Genuinely better — native binary has no interpreter tax. This is the port's best number.
- But: the *allocator-counted* peak (the number the budget gate actually checks) is 0.0 MB in every run — its ratio to prediction is undefined, and the gate compares against it. And for the real model (Qwen3 1.7B, predicted 3.209 GB) **no measured number exists at all** — generation on real weights is v0.2. So the credibility gap is closed for the toy config and unmeasured where it matters.

## 3. Attacks that FAILED (do not repeat)

- **A-overflow**: no path. Sizes ride `saturating_add`; `Layout::size` ≤ `isize::MAX` so `as u64`/`as i64` cannot overflow. (Code-verified.)
- **A-realloc-growth**: defended. 1 KiB→8 KiB growth against a 4 KiB ceiling on a live instance returned null. (Executed, `alloc-attack 4`.)
- **A-check-then-raise-ceiling**: defended. `alloc` re-checks the ceiling independently of `check()`, so a ceiling installed after `check()` still refuses. (Executed, `alloc-attack 5`.)
- **A-freed-then-reallocated false trip**: defended; unit test `freed_then_reallocated_does_not_false_trip_ceiling` green in suite.
- **A-alloc_zeroed path**: defended. Direct over-ceiling `alloc` and `alloc_zeroed` both return null. (Executed, `dbg` example.)
- **A-GGUF array-count bomb** (`count = u64::MAX`): no hang, no OOM — `read_exact` hits EOF and the loop breaks in 40 µs. Downgraded to F11 (silent `Ok`), not a DoS. (Executed, `ggufbomb`.)
- **A-allocator-elision false positive**: first `attack1` "success" was LLVM dead-store elimination of an unread `vec!`, not a ceiling defeat — forcing live reads (`black_box`/checksum) reproduces the abort. Cautionary tale for future reviewers: always make attack allocations observable.

## 4. Ranked improvements (problem → change → proving test → effort)

1. **Wire the ceiling into `admit`/`verify`/`stress`** (fixes F1, the load-bearing hole). Problem: enforcement dead in production. Change: `admit` installs `ALLOCATOR.set_ceiling(min(budget, predicted))` before any execution; `verify`/stress clear it after; document that breach = process abort (F6), and add a subprocess test that runs an over-budget generate and asserts SIGABRT/exit-134 rather than silent success. Effort: medium.
2. **Gate `verify` on the OS number too** (fixes F2). Problem: VmHWM can exceed budget with exit 0. Change: `budget_respected = allocator_ok && vmhwm <= budget` (keep both fields; print which bound failed). Proving test: `verify --budget-gb 0.055` must exit 2 naming the VmHWM bound. Effort: small.
3. **Report absolute allocator peak, not warm-process delta** (fixes F3). Problem: delta ≈ 0 makes the gate unfalsifiable. Change: construct weights *inside* the measured closure (or fork a child per config) and report `peak_after` as the process peak; assert it within ±X% of predicted in stress. Proving test: every stress summary line shows `allocator_peak > 0` and `|allocator − predicted|/predicted < 0.5`. Effort: medium (child-per-config is the clean fix; in-closure construction is the cheap one).
4. **Execute the degradation you emit** (fixes F4). Problem: records describe configs never run. Change: thread `applied_degradation.quant/context` into engine construction in `cmd_verify`/`cmd_stress`; stress asserts the degraded run's measured peak < the base prediction. Effort: medium.
5. **Backstop the bypass class with VmHWM + docs** (bounds F5). Problem: mmap/stack memory bypasses the counter. Change: F2's gate (VmHWM is the backstop) + a README Limitations paragraph naming mmap/thread-stack/static explicitly, with the 64 MiB/32 MiB attack numbers. Proving test: a committed attack-harness test asserting `VmHWM − allocator_peak ≥ 60 MB` after a System alloc (documents the delta instead of hiding it). Effort: small.
6. **Decide what breach means: abort or error** (resolves F6). Problem: crash is loud but not a "refusal". Change either (a) document abort semantics as the enforcement story and downgrade `DoesNotFit`-via-`check()` to advisory pre-flight, or (b) route the engine's large allocations through `try_reserve`/`check()` choke points so breach surfaces as `Err(DoesNotFit)` with the binding constraint. Proving test: over-budget `generate` returns `Err` containing the constraint string (option b) — no abort. Effort: large for (b), small for (a); recommend (a) now, (b) with the weight loader in v0.2.
7. **Make `--probe` real or delete the promise** (fixes F8). Problem: comment promises a flag that doesn't exist; predictions never calibrated. Change: parse `--probe` in `plan`/`admit`/`verify` to call the real `probe()`; default stays synthetic for speed but README says so. Proving test: `plan --probe` on this box prints bandwidth ≈ 11.5 GB/s, differing from synthetic. Effort: small.
8. **Differential oracle test vs the Python edition** (fixes F9 + spec §3.5). Problem: "checked against Python" is unproven. Change: golden file of Python `fitsproof` outputs (weight/KV bytes, verdicts on shared configs) checked into `tests/oracle_golden.json` + a test comparing Rust outputs exactly. Effort: medium (needs the Python venv at dev time only).
9. **Harden the four weak traceability experiments + CI gate** (fixes F10 + second half of F9). Problem: no-op-surviving tests. Change: RoPE KAT at non-zero position (hand-computed rotation), xoshiro reference vector (first output for a fixed seed), TTFT factor-2 KAT, distinct experiments for rows 2 and 8; add `scripts/check_research_traceability.py` failing CI on rows without implementation+experiment+live link. Effort: small–medium.
10. **GGUF reader: `Err` on truncation** (fixes F11). Problem: corrupt input → `Ok` with dropped keys. Change: propagate the read error instead of `break`. Proving test: the `u64::MAX`-count bomb returns `Err`, and a golden truncated file returns `Err`. Effort: small.
11. **Fix `gpu_memory_bytes` misuse** (fixes F12). Zero or real VRAM probe; never VmHWM. Effort: small (one line + test asserting the field is 0 on this GPU-less box).
12. **Record the mutation score** (closes F13/DoD-2). `cargo-mutants` is installed; run it over `allocator`/`plan`/`admit`/`verify`/`cost` on a fast profile (the 96 s probe tests dominate — consider shrinking or splitting them first) and file `reports/mutation-c1.json`. Effort: medium (mostly compute).

## 5. Ship verdict

**No — not as a proof of the memory contract, not yet.** An employer running the binary would find a tool that predicts carefully, refuses loudly at the planning layer, and measures honestly — wrapped in genuinely good engineering hygiene (fmt/clippy green, 73 tests, candid evidence files, no forbidden claims). But the one sentence the repo exists for — the budget is a *hard ceiling*, not a prediction — is not true of any shipped code path: the ceiling is never installed (F1), the proof harness cannot fail (F2/F3), and the degradations it advertises are never executed (F4). Those are not rough edges; they are the claim. Fix improvements 1–4 and this becomes shippable and genuinely differentiated (the 1.0× VmHWM ratio on the reference model is real and beats the Python edition's 7.7×); as it stands, publishing it as a *proof* invites exactly the adversarial reading an employer will give it — and the code will lose that reading.
